# Source contract

How the lastfomo site is laid out, so every tool (and every future session) agrees on it.

## Files

| Path | Role | Edited by |
|---|---|---|
| `brand/tokens.json` | Colours, themes, wing modes, type, motion, layout. Single source of truth. | hand |
| `brand/ledger.json` | Facts, approved lines, banned phrases, British spelling, placeholders, media rights. | hand, owner-approved |
| `brand/marks/*.svg` | Exact Figma vectors: horse (Logo/Mark 9:3), wordmark (9:5), lockup (9:7), glyphs. | never by hand |
| `site/index.html` | The page: a full HTML document with hash routes `#/`, `#/machina`, `#/hortus`, `#/arca`, `#/start`, and the walk at `#/explore` and `#/explore/<wing>`. | hand |
| `site/tokens.css` | Generated from `brand/tokens.json` by `tools/build.mjs`. | generated |
| `site/styles.css` | Component styles. Colours only through `var(--token)`; no hex, rgb or named colours. | hand |
| `site/boot.js` | Runs in `<head>` before first paint: adds the `js` class that gates reveals, restores the saved theme. | hand |
| `site/main.js` | Behaviour: plates, reveals, routing, header trail, curtain, player and film picker, cursor, brief composer, theme switch. Owns the walk’s routes and calls `window.lfExplore` (`enter`, `leave`). | hand |
| `site/explore.js` | The walk: the house and its three wings in 3D, in the spirit of PolyFauna. Worlds, signals and their panels, the score (Web Audio, generated live), auto walk, the round walk button, look by drag or by the phone’s motion, the settings. Loads three.js only when the walk first opens. Colours come from the tokens; the brand check reads it like `main.js`. | hand |
| `site/vendor/three.min.js` | three.js r128 (MIT), byte for byte npm’s `three@0.128.0` `build/three.min.js`, which is also cdnjs’s r128. The web build serves it (`script-src 'self'`); the Artifact loads the cdnjs copy pinned to this file’s sha512. Never edited; not brand-checked. | never by hand |
| `api/brief.mjs` | Vercel Function `POST /api/brief`: checks the brief (same origin, honeypot, at least 3 s on the form, the form’s own wing and timeline values, length caps) and emails it to `BRIEF_TO` (default lastfomo@gmail.com) through Resend with `RESEND_API_KEY`. Answers 503 without a key. Stores and logs nothing of the brief. | hand |
| `site/media.json` | Video manifest. `loops`: per wing `{ "av1", "mp4" }` made by `tools/media/video_to_loop.py` from the owner’s MP4 preview (`media/<wing>-loop-source.mp4`, 960×1280), or `null` to keep the poster: `mp4` is H.264 for every browser (the preview as supplied when it already fits), `av1` (10-bit, only where the H.264 had to be squeezed to fit) is for wide screens that decode it; each under 1.2 MB, 3:4 like the arch, poster `media/<wing>-loop.jpg` (the first frame, under 80 KB). A loop plays round for as long as its screen is the active one, starts over each time its screen comes back, and pauses off screen, while a film is open and while the tab is hidden. It has no pause control, by the owner’s choice (26 October 2026); reduced motion keeps the poster. The Artifact carries the H.264 files only. `covers`: per wing `{ "av1", "mp4" }`, the case cover footage: the owner’s AV1 file as supplied (2560×1440) and an H.264 copy (1280×720), each under 1.2 MB, poster `media/<wing>-cover.jpg` (first frame). Wide screens that decode AV1 take it; phones and everything else take the H.264 copy; a browser that decodes neither keeps the poster. The Artifact carries the H.264 copy only. `films`: per wing `{ "youtube": "<id>", "duration": "m:ss" }`. The build adds `embed` (true for web, false for the Artifact) and, on the web build only, `brief` (`/api/brief`, where the form posts). | hand |
| `site/media/*.jpg` | Posters and stills. Every file has an entry in `brand/ledger.json` → `media`. The `*-loop-source.mp4` files beside them are the owner’s loop previews (26 October 2026), the sources of the loops; the build ships only what the page references. `shop-<product>.jpg` are the maker’s product photos, resized from `shop/source/img/`. | hand |
| `site/shop.json` | The shop and the two previews. The Hortus hardware: maker, currency (`code`, `symbol`, and `name` as the copy says it; how prices are set is in `$prices`), the Hardware screen, the hardware view (groups, ordering steps) and each product (`slug`, `name`, `kind`, `line`, `lead`, `price` as a whole number, `image`, `alt`, `does`, `specs`, `box`). Written in English by hand from `shop/source/emode.json`. `"live": false` keeps it off the web build. `machina`: the Machina preview (`screen`: `code`, `title`, `lead`, `outlook` (what the answering line says at rest), `note` (the chart’s caption) and `cta`; `study`: a row per machine with `name`, `kind`, `points` (launch price first, latest last, in US dollars) and `story`, the line the row writes when chosen). `arca`: the Arca preview (`screen` with `notes`, the Vault and Artists lines; `tabs`, each with `id`, `label` and the `text` it writes; `gold`: `unit`, the month-end `closes` and `now`, the latest price; `art`: `unit`, `years` as `[year, billions]` and `note`). Every number in them is a dated, sourced fact in `brand/ledger.json` (`machina.study.*`, `arca.study.*`). | hand |
| `tools/icons.mjs` | Draws the icons `tools/build.mjs` writes at the web build’s root: `favicon.svg`, `favicon.ico` (16, 32, 48) and `apple-touch-icon.png` (180), the horse from `brand/marks/horse.svg` whole and centred at 80% of the width, paper on a void square, colours from `brand/tokens.json`. `site/index.html` links them; the Artifact leaves them out. | hand |
| `tools/shop/render.mjs` | Renders `site/shop.json` at the six markers in `site/index.html`, each on its own line: `<!-- shop:bar -->` (the basket button), `<!-- shop:hardware -->` (the Hardware screen on the Hortus case), `<!-- shop:machina -->` and `<!-- shop:arca -->` (the Machina and Arca previews on those cases, from `tools/shop/previews.mjs`), `<!-- shop:views -->` (the hardware views), `<!-- shop:basket -->` (`dialog#basket` and the `#lf-shop` data). Shared markup helpers live in `tools/shop/html.mjs`. One line of markup per marker, so line numbers in reports hold. The brand check always checks the page with the shop in place. | hand |
| `shop/emode-products.json`, `shop/source/` | The maker’s product pages, and what `tools/shop/import-emode.mjs` brings back from them (the maker’s own Russian text, price, stock, photos). Refreshed by the `shop-import` workflow. Nothing here ships. | workflow |
| `dist/web/` | Build output for any static host (Vercel): a full document with its CSS and JS as files (no inline script, so the strict CSP in `vercel.json` holds), `media/` and `vendor/three.min.js` beside it. Every media URL carries its content hash (`?v=`), because `/media/` is cached for a year; the manifest names three.js with its hash too (`three`). | generated |
| `dist/artifact/lastfomo.html` | Build output for a claude.ai Artifact: a fragment (no doctype/html/head/body), CSS, JS and images inlined. A photo shown more than once (the shop’s, on its cards and shelves) travels once, in `script#lf-pics`, and a small script fills each `img[data-pic]`, templates included, before the page’s own scripts run. Always carries the shop. Its manifest points the walk at cdnjs’s three.js r128 with the vendored copy’s hash (`three`, `threeIntegrity`). | generated |
| `dist/preview/` | While the shop is not live: the web build with the shop in place, for QA. Never deployed (`vercel.json` serves `dist/web`). | generated |

## Markup conventions

- `main.view[data-view]` per route, optional `data-wing` on case views.
- `section.screen` per full-screen step, optional `data-wing="machina|hortus|arca"`. House-level screens carry no `data-wing`.
- `.word` is the only class set in Jacquard 24, and its text is exactly one of `lastfomo`, `machina`, `hortus`, `arca`.
- `.code` labels follow `CODE — Wing · Discipline` (e.g. `MCH — Machina · Autonomous AI`).
- `canvas.plate[data-plate="machina|hortus|arca|paper"]` is a live stipple plate holding the whole horse.
- `.naves`, and any row whose children carry all three wings (the film cards, the brief pills), runs hortus, machina, arca.
- `data-go` and `data-scroll` name an `id` that exists; the build fails otherwise.
- `[data-count]` marks a stat that counts up once; its final text is in the markup.
- `button#theme` cycles the theme preference `auto → dark → light` and sets `data-theme` on `<html>` (no attribute for auto).
- Images use `src="media/<name>.jpg"`, video posters `poster="media/<name>.jpg"`.
- `form#brief` carries a honeypot, `label.hp > input[name="website"][tabindex="-1"]`, hidden from sight and from assistive technology. Its wing radios and timeline options must match `WINGS` and `TIMELINES` in `api/brief.mjs` (`tools/brief.test.mjs` checks). `#sent-title` reads “Brief sent.” after the endpoint confirms, otherwise “Brief ready.” with copy and mailto.
- The header brand link holds one exact mark: the horse alone (`brand/marks/horse.svg`, `viewBox="0 0 420 120"`), the owner’s choice. Beside it, `nav#crumbs` names where you are, like a directory (“Home / Machina”), and stays hidden on the house. A view joins the trail with `data-crumb="<name>"` and, below another page, `data-crumb-parent="<view>"` (Hardware sits under Hortus, a product under Hardware). The right side holds “Start a project” (and the basket while the shop is on).
- The walk: `main.view#view-explore[data-view="explore"]` with `data-crumb="Explore"` and `data-crumb-icon="lux"`, so the trail shows the Lux glyph: “Home / Explore”, then “Home / Explore / Hortus” inside a wing. `#/explore/<wing>` opens a wing directly; `#explore-<wing>` does too, for Artifact links that pass only plain anchors. Walking into an arch sets the route, and the route moves the walk (`lfExplore.enter(wing)`), so the trail, the title and Back follow. While it is open `body.xp-on` hides Start a project, the progress bar and the dots index and shows `button#xp-menu` (the settings, `dialog#xp-set`), and `<html data-theme="dark">` holds until the visitor leaves. The hero’s Explore (`a[href="#/explore"]`) opens the house; each case cover carries Explore beside Play the film (`a[href="#/explore/<wing>"]`). The Arca objects ride in `template#xp-media` as ordinary `img[src="media/…"]`, so the build inlines or fingerprints them like any image. `window.lfExplore.peek()` reports the walk’s state for the QA tools.
- Every film control is `<a data-play="<wing>" href="https://www.youtube.com/watch?v=<id>" target="_blank" rel="noopener">`; the id must match `site/media.json`. Where the page can play a film (`site/main.js`, `inPage`) it opens in `dialog#reel`; otherwise the link opens YouTube. `[data-reels]` (“Watch the films”) opens the same dialog on `#reel-pick`, the three film cards to choose from; the landing has no films screen of its own.
- A case view opens on `section.case-cover`: the label, the wordmark and the line stacked tight, one lead, one “Play the film”, bottom-aligned over `.cover-bg[aria-hidden="true"] > video.cover-v[data-cover="<wing>"]`, the wing’s footage full-bleed under a fall from void to clear. The footage loads when its cover is first active and loops for as long as the cover is the active screen of the open page and the tab is in view; anywhere else it pauses. There is no pause control, by the owner’s choice (26 October 2026); reduced motion keeps the poster, as does a browser that cannot play the footage. The cover stays dark in both themes.
- The Hortus hardware: `#/hardware` is `main.view[data-view="hardware"]`, `#/hardware/<slug>` is `main.view[data-view="hw-<slug>"]`; both carry `data-wing="hortus"` and a `data-page-title`. A page built without the shop sends these routes to the Hortus case. Product photos sit on paper in a square `span.tile.goods`, sealed in grey until their screen is active; the shop has no arches (subpages use square cards). The Hardware screen on the Hortus case, `section#hortus-hardware`, shows every product on a shelf: `ul.shelf` of `li.good.mini` cards (photo, name, kind, price), one row on desktop, three to a row on tablets, sideways on phones. The hardware list is one packed screen: a `div.cat-g` per group of `li.good` cards (kind, name, line, the two specs named in the product’s `keys`, price). A product page opens on `section.pdp`: the photo in a square card beside the name, line, price, basket buttons and key specs; then `ul.does` (what it does, in cards), the specification, and the order with the rest of the hardware on a shelf, starting from the next product. A card’s `h3.gn a` is its link, and its hit area covers the card. The shop’s views (`main.view.shop-v`) snap by proximity and let a screen grow past the window. `[data-add="<slug>"]` adds one to the basket and opens it; `[data-basket]` opens it. The basket lives in `localStorage` (`lf-basket`) and sends its order as an email (mailto with copy); nothing is charged on the page.
- The previews, one screen each: `section.screen.pv#machina-build` on the Machina case and `section.screen.pv#arca-vault` on the Arca case, each before the wing’s “Next”. The words, `div.pv-t`, hold the label, the title, the lead, `p.live[aria-live="polite"]` (the line the chart answers into) and one button, beside the chart. Machina’s chart is `figure.db`, a price study on a log axis from $700 to $20,000: one `button.db-r[aria-pressed]` per machine with its name and kind, `span.db-p` (the bar `i.db-b` from launch price to latest; a hollow dot at launch, a small dot for each price between, a solid dot at the latest) and both prices written out. Choosing a row, or pointing at it with a fine pointer, writes its `data-story` into the live line and dims the other rows (`.db.dim`); choosing it again writes the outlook back. Arca’s is `figure.pv-fig`: `div.tabs[role=tablist]` with a `[role=tab]` button per market (the arrow keys move between them) over its `div.pv-panel[role=tabpanel]`, and choosing a tab writes its `data-text` into the live line. The gold panel is `div.gl-plot[data-points]` (an SVG line and area, HTML ticks and labels, the record month and the latest price marked, a crosshair and tooltip that follow the pointer or the arrow keys); the art panel is `div.ac`, a column a year (the latest in the wing colour, the rest grey; the latest and the peak labelled, every column showing its value on hover or focus). Each chart has a `table.sr` twin. Below 900px a preview stacks label, title, lead, chart, live line and button, and leaves out the Vault and Artists notes (`dl.pv-notes`); the lead says the same. The brand check reads `data-story` and `data-text` as page text.

## Commands

| Command | Does |
|---|---|
| `node tools/build.mjs` | Regenerates `site/tokens.css`, runs the brand check, writes `dist/web/` and `dist/artifact/lastfomo.html` (and `dist/preview/` while the shop is not live). Fails on brand errors. |
| `node tools/brandcheck.mjs` | Checks the source (`site/`). `--html <file>` checks one self-contained page. `--json` for machine output. Exit 1 on errors. |
| `node tools/brandcheck.test.mjs` | Fixture tests for the brand check. |
| `node tools/brief.test.mjs` | Tests for `api/brief.mjs` with the email API mocked: sending, the 503 without a key, origin, method, honeypot, timing, validation, size, and the form’s values. |
| `node tools/qa/shoot.mjs` | Headless screenshots of every screen of every route, desktop 1440×900 and phone 390×844, dark and light, plus contact sheets and a JSON report in `out/qa/`. |
| `node tools/qa/smoke.mjs` | Clicks through routes, the header trail, player and film picker, case covers, brief form and theme switch; reports console errors. |
